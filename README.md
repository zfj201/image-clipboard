# 图片自动复制

<img src="artwork/icon.png" width="96" alt="图片剪贴板图标" />

一个完全免 Root 的 Android 图片剪贴板工具。系统相机、截图，以及其他应用保存到媒体库的新图片，都可以在后台自动复制。**不限于 Camera 和 Screenshots 目录。**

## 覆盖范围

| 图片来源 | 处理方式 |
| --- | --- |
| 系统相机、系统按键／三指截图 | 全媒体库观察与补查 |
| 第三方相机、应用内截图、聊天保存、编辑导出 | 保存到系统媒体库后自动发现，不限定目录 |
| 未进入媒体库、但可以授权访问的文件夹 | 系统文件夹选择器授权，每30秒增量比较 |
| 应用私有图片、临时图片、云端图片 | 从原应用通过“分享”发送到本工具，或手动选图 |

免 Root 无法主动读取其他应用的私有目录、内存图片和加密缓存。Android 11+ 也禁止用文件夹授权访问 `Android/data`、`Android/obb` 等位置。图片没有落盘、没有媒体记录、也未被分享／授权时，本应用无法自动获取；不会申请 Root、无障碍、录屏或“所有文件访问”权限。

## 功能

- 所有外部媒体存储卷的图片观察器，正常事件触发后短暂等待保存完成；每15秒补查近期记录。
- 额外授权文件夹单独扫描，避免文件夹提供器较慢时阻塞媒体库监听。单轮最多5000项、递归24层，建议授权具体图片子目录。
- 等待 `IS_PENDING` 结束，对文件完整解码验证后再复制。不会仅把文件路径文字放到剪贴板。
- 对相同来源计算 SHA-256，合并重复通知，处理内容覆盖；校验提交顺序，减少旧图片覆盖新图片。
- 包含／排除关键字、最小边长、可选“只处理疑似拍照／截图”。默认处理所有新保存图片，兼顾非标准应用目录。
- JPEG、PNG、WebP、GIF，以及系统支持解码的 HEIF/AVIF 等格式。可选将 HEIF、AVIF、BMP 转成 JPEG（长边最多4096px），原图不变。
- 只读图片 ContentProvider，通过系统剪贴板授予接收应用读取权限；支持历史重复制、手动选图、分享接收和预览验证。
- 常驻前台服务、开机／覆盖升级恢复。暂停后不再自动复制。
- 无网络权限、无广告、无账号。缓存仅保留本机，按7天／256MB／150个文件的上限清理，最近复制的一张优先保留；本地历史最多200条。
- 自适应启动图标及 Android 13+ 主题单色图标，矢量源文件位于 `artwork/` 与 Android resources。

## 使用

1. 安装并打开应用，点“开启自动复制”，选择允许访问**所有照片**，允许通知。
2. 在系统设置中允许自启动、取消电池限制，保留运行通知。
3. 拍照或截图，等图片保存完成后，到支持图片粘贴的应用中粘贴。
4. 不在相册里的图片，可添加其可访问的文件夹；仍无法读取的图片，从原应用分享至“图片自动复制”。

部分输入框只支持文本粘贴，部分输入法提供图片候选。剪贴板中存在图片不等于所有聊天应用都会提供“粘贴图片”按钮。Android 13+ 会自动清理较久未使用的剪贴板，可在本应用重新复制历史图片。文件夹模式由文档提供器的时间／大小信息识别变化；提供器不报告变更时，不能保证捕获每次覆盖。

应用首次开启不导入旧相册。启用之后的新保存／变更图片会被处理，批量下载、相册迁移也可能被当作新保存图片；可暂停或配置筛选规则。相机、图库的内部缓存图片不会被声称为完整覆盖。

## 构建与签名

Android Studio、JDK 21、Android SDK 37、Python非必需；**不需要 NDK**。`local.properties` 填写本机 `sdk.dir`。

```sh
./gradlew :app:assembleDebug :app:lintDebug
./gradlew :app:assembleRelease :app:lintRelease
sh scripts/test-core.sh
```

测试包：`app/build/outputs/apk/debug/app-debug.apk`，包名 `com.zfj.imageclipboard.debug`，显示为“图片自动复制·测试”。与正式包独立，方便在正式签名之前验证。

正式包：包名 `com.zfj.imageclipboard`。可使用 Android Studio 的 **Generate Signed App Bundle / APK → APK → release** 选择自己的 JKS；也可复制 `keystore.properties.example` 为 `keystore.properties`，填写本地密钥信息后运行 `assembleRelease`。

- 配置签名时输出 `app/build/outputs/apk/release/app-release.apk`。
- 没有签名配置时输出 `app-release-unsigned.apk`，**不能直接安装**。
- JKS、密码文件、本机SDK路径均被 `.gitignore` 排除。不要上传密钥和密码。
- 后续正式版本必须使用同一签名才能覆盖更新。
- 测试版和正式版的设置独立；安装正式版后，应暂停／卸载测试版，避免两份同时复制。

## 测试

`scripts/test-core.sh` 在电脑上测试路径规则、图片类型判断和旧图片提交顺序。`probe` 是仅供开发使用的独立测试 APK，可以用另一个应用 UID 保存图片、分享内部私有图片，以及读取并解码剪贴板图片；不会打进主应用安装包。

实机结果与验证边界见 [TESTING.md](TESTING.md)。

## 工程结构

- `MonitorService`：前台服务、媒体观察、近期补查和卷变化。
- `FolderScanner`：用户授权的 SAF 文件夹扫描。
- `PicturePipeline`：完整性校验、规则、指纹、格式兼容和剪贴板提交。
- `ImageProvider`：私有缓存的只读 URI 及剪贴板读授权。
- `MainActivity` / `ShareActivity`：设置、历史、手动选图和分享入口。
- `probe`：跨应用验证工具。

本项目不包含任何 Root 守护进程、Xposed 模块或绕过应用私有存储权限的实现。
